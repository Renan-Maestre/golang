# 🧪 Testes em Go

Testes fazem parte dos estudos deste repositório, principalmente porque o próprio Go oferece uma excelente integração nativa através do package:

```go
testing
```

Os arquivos de teste normalmente utilizam o padrão:

```text
arquivo_test.go
```

Por exemplo:

```text
adicionar.go
adicionar_test.go
```

Para executar os testes de um package:

```bash
go test
```

Para visualizar mais informações:

```bash
go test -v
```

Para testar todos os packages do projeto:

```bash
go test ./...
```

# 💡 Exemplo simples

## Implementação

```go
package inteiros

func Adicionar(x, y int) int {
	return x + y
}
```

## Teste

```go
package inteiros

import "testing"

func TestAdicionar(t *testing.T) {
	resultado := Adicionar(2, 2)
	esperado := 4

	if resultado != esperado {
		t.Errorf(
			"resultado %d, esperado %d",
			resultado,
			esperado,
		)
	}
}
```

Executando:

```bash
go test
```

Resultado esperado:

```text
PASS
ok
```

# 🔴 🟢 🔵 TDD

Embora o repositório **não seja exclusivamente sobre TDD**, essa metodologia é utilizada em alguns estudos para aprender desenvolvimento orientado por comportamento e testes.

O ciclo tradicional do **Test Driven Development** funciona da seguinte maneira:

```text
        ┌─────────────┐
        │ 🔴 RED      │
        │ Criar teste │
        └──────┬──────┘
               │
               ▼
        ┌─────────────┐
        │ 🟢 GREEN    │
        │ Fazer passar│
        └──────┬──────┘
               │
               ▼
        ┌─────────────┐
        │ 🔵 REFACTOR │
        │ Melhorar    │
        └──────┬──────┘
               │
               └───────────────► Repetir
```

### 🔴 RED

Criamos um teste representando o comportamento esperado.

Inicialmente o teste deve falhar.

### 🟢 GREEN

Implementamos o necessário para fazer o teste passar.

### 🔵 REFACTOR

Com os testes funcionando, melhoramos a implementação sem alterar o comportamento esperado.

# ⚡ Concorrência

Um dos pontos que mais pretendo explorar durante os estudos é o modelo de concorrência do Go.

Alguns dos conceitos presentes ou planejados para o repositório são:

```go
go minhaFuncao()
```

### Goroutines

Permitem executar funções concorrentemente de maneira simples e leve.

### Channels

Permitem comunicação entre goroutines:

```go
ch := make(chan int)
```

### Select

Permite aguardar operações em múltiplos channels.

### Mutex

Pode ser utilizado para controlar acesso concorrente a dados compartilhados.

### WaitGroup

Permite aguardar a conclusão de várias goroutines.

### Context

Muito utilizado para controle de cancelamento, timeout e propagação de informações entre operações.
